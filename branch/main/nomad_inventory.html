benemon.nomad.nomad inventory – Nomad client nodes, server members and allocations as hosts

Note

This inventory plugin is part of the benemon.nomad collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install benemon.nomad. You need further requirements to be able to use this inventory plugin, see Requirements for details.

To use it in a playbook, specify: benemon.nomad.nomad.

New in benemon.nomad 0.2.0

  • Synopsis

  • Requirements

  • Parameters

  • Notes

  • Examples

Synopsis

  • Lists the client nodes of a Nomad cluster as hosts, and on request its server members and running allocations.

  • Host variables are the Nomad API documents with the API’s field names, carrying every address the API attaches to a host. A client node or server member has one address and gets it as ansible_host; an allocation has several and gets none, so the play chooses with compose.

  • Allocation hosts carry the allocation ID and namespace that benemon.nomad.nomad_exec needs.

  • Reads a YAML configuration file whose name ends in nomad.yml or nomad.yaml.

Requirements

The below requirements are needed on the local controller node that executes this inventory.

  • nomadpy >= 0.2.0

Note

Configuration entries listed above for each entry type (Ansible variable, environment variable, and so on) have a low to high priority order. For example, a variable that is lower in the list will override a variable that is higher up. The entry types are also ordered by precedence from low to high priority order. For example, an ansible.cfg entry (further up in the list) is overwritten by an Ansible variable (further down in the list).

Notes

Note

  • Connection options fall back to the environment variables the Nomad CLI reads, with the same meaning.

  • Enterprise features are not checked client-side. On a Community server the request fails with the server’s own error.

  • Inventories are not finalized at this stage, so the auto populated all and ungrouped groups will only reflect what previous inventory sources explicitly added to them.

  • Runtime ‘magic variables’ are not available during inventory construction. For example, groups and hostvars do not exist yet.

Examples

# cluster.nomad.yml: client nodes, grouped by datacenter, node pool, class, status, eligibility and driver
plugin: benemon.nomad.nomad
address: https://nomad.example.com:4646

# Server members and running allocations as well
plugin: benemon.nomad.nomad
servers: true
allocations: true

# Virtual machines run as allocations: reach each guest at the host-mapped port its group labels "ssh"
plugin: benemon.nomad.nomad
clients: false
allocations: true
namespace: vms
compose:
  ansible_host: (nomad_allocation.AllocatedResources.Shared.Ports | selectattr('Label', 'eq', 'ssh') | first).HostIP
  ansible_port: (nomad_allocation.AllocatedResources.Shared.Ports | selectattr('Label', 'eq', 'ssh') | first).Value
keyed_groups:
  - key: nomad_allocation.JobID
    prefix: vm

# Or at the address a task registered as the Nomad service "ssh"
plugin: benemon.nomad.nomad
clients: false
allocations: true
services: true
compose:
  ansible_host: (nomad_services | selectattr('ServiceName', 'eq', 'ssh') | first).Address
  ansible_port: (nomad_services | selectattr('ServiceName', 'eq', 'ssh') | first).Port
