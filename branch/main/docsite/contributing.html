Contributing

The repository is benemon/ansible-collection-nomad. The collection talks to Nomad through nomadpy only; a change that needs a new API call starts in nomadpy.

Local setup

Create .venv at the repository root with ansible-core, nomadpy and pytest on Python 3.14, and have rsync on the path. ansible-test needs the collection in an ansible_collections/benemon/nomad directory, so the Makefile copies the repository to one under $TMPDIR before each target.

make sanity
make units
make integration

Test lanes

Integration tests start a Nomad dev agent with ACLs enabled from a binary named explicitly, bootstrap it, and run ansible-test integration against it. There are two lanes, and each is selected by its variables. A lane whose variables are unset is skipped; a run with no lane set fails.

Lane

Variables

Community

NOMADPY_TEST_CE_BIN, the path of a Community nomad binary

Enterprise

NOMADPY_TEST_ENT_BIN, the path of an Enterprise nomad binary, and NOMAD_LICENSE_PATH, the path of its licence file

The targets read nomad_enterprise from the lane and assert the Community responses listed in Enterprise behaviour on the Community lane. A target for an Enterprise surface must pass on both.

CI runs sanity, units and integration on the oldest and newest supported ansible-core. It downloads both editions of Nomad and runs the Enterprise lane when the NOMAD_LICENCE repository secret is set, so a fork without the secret runs the Community lane and stays green.

Documentation

The site is built from the DOCUMENTATION, EXAMPLES and RETURN blocks of each plugin and from the pages under docs/docsite/rst/. The build fails on malformed documentation and on a page that references an option, return value or plugin that does not exist, so it is run on every push and pull request. To build it locally:

pip install antsibull-docs
make tree
export ANSIBLE_COLLECTIONS_PATH=${TMPDIR:-/tmp}/benemon-nomad
antsibull-docs sphinx-init --use-current --fail-on-error --squash-hierarchy --dest-dir /tmp/nomad-docs benemon.nomad
pip install -r /tmp/nomad-docs/requirements.txt
/tmp/nomad-docs/build.sh

The result is under /tmp/nomad-docs/build/html.

Changelog

Every user-visible change carries a fragment under changelogs/fragments/, in the antsibull-changelog format. A new plugin carries version_added instead of a fragment and the release step lists it from that. antsibull-changelog lint checks the fragments.

Before a release, antsibull-changelog release folds the fragments into changelogs/changelog.yaml and regenerates CHANGELOG.rst; the fragments are removed in the same step. Commit the result, then tag.

Releases

A release is a tag v<version> matching version in galaxy.yml. The release workflow refuses a tag that does not match, requires a green test run for the tagged commit, builds the collection, publishes it to Ansible Galaxy and creates the GitHub release.
