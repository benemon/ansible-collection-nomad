Getting started

The benemon.nomad collection manages HashiCorp Nomad and Nomad Enterprise over the HTTP API, through the nomadpy client. Every plugin runs on the controller or a delegated host that can reach the API; nothing runs on the Nomad servers themselves.

Install

The collection requires ansible-core 2.19 or newer, Python 3.11 or newer and nomadpy 0.2.0 or newer with its exec extra on the host that runs the plugins.

ansible-galaxy collection install benemon.nomad
pip install -r ~/.ansible/collections/ansible_collections/benemon/nomad/requirements.txt

Connection options

Every plugin takes the same connection options. Each one falls back to the environment variable the Nomad CLI reads, with the same meaning.

default

the region of the server answering

NOMAD_CACERT

NOMAD_CAPATH

NOMAD_CLIENT_CERT

NOMAD_CLIENT_KEY

NOMAD_TLS_SERVER_NAME

NOMAD_SKIP_VERIFY

false

namespace is present only on plugins whose resource lives in a namespace: jobs and variables. ACL resources, namespaces, node pools, nodes, quotas and Sentinel policies are cluster-wide.

The modules form the benemon.nomad.nomad action group, so a play can set the connection once with module_defaults:

- hosts: localhost
  module_defaults:
    group/benemon.nomad.nomad:
      address: https://nomad.example.com:4646
      token: "{{ nomad_token }}"
  tasks:
    - benemon.nomad.nomad_namespace:
        name: web
        description: Web tier

The benemon.nomad.nomad_variable lookup, the benemon.nomad.nomad inventory plugin and the benemon.nomad.nomad_exec connection plugin are outside the action group and do not see module_defaults. Pass their connection options as keyword arguments, inventory file options or ansible_nomad_* host variables, or set the environment variables.

How the modules behave

A state module reads the resource first and reports changed only when the server’s state differs from the options that were set. An option left out keeps its current value on the server. A dict option that is set replaces the whole nested structure. Check mode and diff mode are supported throughout.

Returned resources are the Nomad API documents with the API’s field names, so result.namespace.Name and result.job.TaskGroups read as the API documentation describes them.

A request the server refuses fails the task with the server’s message in msg and the HTTP status in status_code. See Enterprise behaviour for the responses a Community server gives to Enterprise requests.
