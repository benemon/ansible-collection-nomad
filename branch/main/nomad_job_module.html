benemon.nomad.nomad_job module – Register or stop a Nomad job

Note

This module is part of the benemon.nomad collection (version 0.1.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install benemon.nomad. You need further requirements to be able to use this module, see Requirements for details.

To use it in a playbook, specify: benemon.nomad.nomad_job.

New in benemon.nomad 0.1.0

Synopsis

  • Register a job from its specification, or stop it.

  • Whether a registration changes anything is decided by the server’s plan endpoint, so an unchanged job reports no change.

  • The diff shows the job on the server before and the submitted document after.

  • A value is given in one place only. name, namespace and region fail the task when the specification also carries ID, Namespace or Region; nothing is overridden and nothing is ignored. A document read back from the API carries all three, so it is registered without those options. A Namespace or Region in the specification is the one the job is read and planned in.

  • By default the module waits for the evaluation and, for service jobs, for the deployment to finish, and fails when allocations cannot be placed or the deployment fails.

Requirements

The below requirements are needed on the host that executes this module.

  • nomadpy >= 0.2.0

Parameters

Parameter

Comments

address

string

Address of the Nomad HTTP API, including the scheme.

Falls back to NOMAD_ADDR, then http://127.0.0.1:4646.

ca_cert

path

Path to a CA certificate file to verify the server against.

Falls back to NOMAD_CACERT.

ca_path

path

Path to a directory of CA certificates to verify the server against.

Falls back to NOMAD_CAPATH.

client_cert

path

Path to the client certificate for TLS authentication.

Falls back to NOMAD_CLIENT_CERT.

client_key

path

Path to the private key of client_cert.

Falls back to NOMAD_CLIENT_KEY.

hcl_variables

dictionary

Values for the variable blocks of an HCL specification, passed to the server’s parse endpoint.

Only for HCL input; the task fails when jobspec is a document. Values are strings, numbers, booleans or lists of those.

jobspec

any

The job specification as HCL text, as a JSON document in text, or as the document itself.

HCL is converted by the server, so it must be valid for the server’s version, and is registered with its source as the job’s submission, the record nomad job run keeps and the UI shows as the job spec. The document is the shape nomad job run -output prints and the API documents.

Required when state=present.

name

string

The job ID, for state=absent.

A specification carries its own ID, so name cannot be set with jobspec.

namespace

string

Namespace the resource lives in.

Falls back to NOMAD_NAMESPACE, then default.

policy_override

boolean

Override soft-mandatory Sentinel policies. Enterprise.

Choices:

  • false ← (default)

  • true

purge

boolean

With state=absent, remove the job from the server rather than leaving it stopped.

Choices:

  • false ← (default)

  • true

region

string

Region to send requests to.

Falls back to NOMAD_REGION, then the region of the server answering.

skip_verify

boolean

Do not verify the server certificate.

Falls back to NOMAD_SKIP_VERIFY.

Choices:

  • false

  • true

state

string

Whether the job should be registered or stopped.

Choices:

  • "present" ← (default)

  • "absent"

timeout

integer

Seconds to wait before giving up when wait=true.

Default: 300

tls_server_name

string

Server name to verify the certificate against instead of the host in address.

Falls back to NOMAD_TLS_SERVER_NAME.

token

string

ACL token secret sent with every request.

Falls back to NOMAD_TOKEN.

wait

boolean

Wait for the evaluation to complete and, for service jobs, for the latest deployment to reach a terminal status.

Failed placements and failed deployments fail the task.

Choices:

  • false

  • true ← (default)

Notes

Note

  • Connection options fall back to the environment variables the Nomad CLI reads, with the same meaning.

  • Enterprise features are not checked client-side. On a Community server the request fails with the server’s own error.

Examples

- name: Register a job from an HCL file and wait for its deployment
  benemon.nomad.nomad_job:
    jobspec: "{{ lookup('ansible.builtin.file', 'web.nomad.hcl') }}"

- name: Register a job from an HCL template
  benemon.nomad.nomad_job:
    jobspec: "{{ lookup('ansible.builtin.template', 'web.nomad.hcl.j2') }}"
    namespace: web

- name: Register an HCL specification that declares variables
  benemon.nomad.nomad_job:
    jobspec: "{{ lookup('ansible.builtin.file', 'web.nomad.hcl') }}"
    hcl_variables:
      count: 3
      image: nginx:1.27

- name: Register a job from its JSON document
  benemon.nomad.nomad_job:
    jobspec: "{{ lookup('ansible.builtin.file', 'web.json') }}"

- name: Stop and purge a job
  benemon.nomad.nomad_job:
    name: web
    state: absent
    purge: true

Return Values

Common return values are documented here, the following are the fields unique to this module:

Key

Description

deployment

dictionary

The latest deployment of the job after waiting, as the API returns it.

Returned: when wait=true and the job has a deployment

eval_id

string

ID of the evaluation the change created.

Returned: when a write was made

job

dictionary

The job as the Nomad API returns it, with the API’s field names, after a write or when nothing changed.

In check mode, the submitted document.

Returned: when state=present
